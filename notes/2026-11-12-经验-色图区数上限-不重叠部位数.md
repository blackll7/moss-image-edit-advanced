# 经验：色图区数上限 = 不重叠部位数

> 2026-11-12。基于 SOP-1 四星2 冰蓝舞娘案例（11 个 grounding 部位），8 步 fast / seed 9001 / 8 裁片 + 8 掩码 + 黑底深度图。
> 结论一句话：**能划几个色区不看颜色，看 bbox 重不重叠。本案例上限 9 区。**

---

## 一、为什么以前只划 3 区（旧归因已作废）

`tools/detail_colormap.py` 里原本有一条硬拦：

```python
if len(zones) > 3:
    print("❌ 色区数 %d > 3 —— 会被理解成多个人。请按部位合并。")
    return 2
```

以及一个只有 5 项、且 `#0000ff` 写了两次的色板（实际 4 色，第 4 区会与第 2 区同色）。

这两处都建立在一个**已被证伪**的归因上：当年出现「多个人」时，真因是 `--control-strength 0.5` —— 那个参数同时缩放 color 与 depth 两半（`moss_control_embedder.py` 的 384 通道 = 128 噪声 + 128 color + 128 depth），0.5 时深度图（锁人体轮廓）被砍半，色图的分区暗示成了主导，于是画出 2–3 个人。**与色区数量无关。**

修好 `--control-strength 1.0` 之后，色区数一路加到 9 都没事。

|---|---|---|---|---|---|---|---|---|
| z3 | 3 | 26.73 | 130.32 | 31.2 | 136.65 | 115.69 | 131.00 | 0.000 |
| z5 | 5 | 42.11 | 129.35 | 33.6 | 136.87 | 115.66 | 128.21 | 0.000 |
| z8 | 8 | 54.20 | 129.62 | 31.1 | 136.14 | 115.71 | 129.69 | 0.000 |

## 三、颜色不是瓶颈（实测 + 理论）

色板曼哈顿距离：

| 色数 | 最小色差 | 最接近的一对 |
|---|---|---|
| 2–4 | **255** | 洋红 ↔ 纯蓝 |
| **5–9** | **127** | **`#ff00ff` ↔ `#8000ff`（洋红 ↔ 紫）** |
| 10 | 127 | `#00ffff` ↔ `#0080ff`（青 ↔ 天蓝） |

色板与中灰底 `(128,128,128)` 的距离恒为 255–382。

**127 的曼哈顿距离对 VAE 的 16 倍下采样完全够分** —— 3/5/8/9 区实测泄漏全是 **0.000%**，10 区也只有 0.042%（噪声级）。所以「一张色图最多三子区」的旧说法，至少在这个用法下不成立。

---

## 四、真正的瓶颈：bbox 重叠

z10 变差的唯一原因是我把 `veil` 也加进去了 —— **`veil` 的 bbox 与 `bodice` 重叠 92%**，色图画的时候是按 zones 顺序后画覆盖先画，`veil` 直接盖掉了 `bodice` 那块。

胸衣局部实测（x 40–60%、y 12–28%）：

| 臂 | 亮度 | **饱和度** | vs参考 |
|---|---|---|---|
| z3 | 183.8 | 34.73 | 110.77 |
| z8 | 185.9 | 32.78 | 110.26 |
| **z9** | 186.0 | **33.38** | **107.96** |
| z10 | 187.4 | **29.11** ↓ | 109.19 |

z10 的胸衣饱和度掉到 29.11（其他都在 32–35），肉眼就是「胸衣被漂白了」。

**本案例的两对重叠**：

```
veil ↔ bodice        92%   （grounding 把头纱和胸衣框成了几乎同一块）
sleeve_l ↔ sleeve_r 100%   （左右袖完全同框）
```

所以 **11 个部位 → 最多 9 个互不重叠的色区**。这不是色板的上限，是 grounding 的上限。

---

## 五、操作规则

1. **色区数不设默认值**，按反查出来的细节条数决定；**只设上限 = 互不重叠的部位数**。
2. **加色区前先查 bbox 重叠**：任意两个部位 IoU > 0.8 就不能同时做色区（后画的会盖掉先画的）。`pick_parts.py` 的 `[dedup]` 日志已经把这类部位列出来了。
3. **色区数 > 3 时必须确认 `--control-strength 1.0 --depth-strength 1.0`**，否则会退化成多个人（这才是当年那个坑）。
4. **色板顺序有意义**：`PALETTE` 按序号分配给 zones，改 zones 顺序会换色，但同一次实验内不影响结果。

## 六、代码侧改动（`tools/detail_colormap.py`）

**色板从 4 色扩到 10 色**：

```python
PALETTE = [
    "#ff00ff",  # 洋红
    "#0000ff",  # 纯蓝
    "#00ff00",  # 纯绿
    "#ff8000",  # 橙
    "#8000ff",  # 紫
    "#00ffff",  # 青
    "#ff0000",  # 纯红
    "#80ff00",  # 黄绿
    "#ff0080",  # 玫红
    "#0080ff",  # 天蓝
]
```

**`>3 区` 从 `return 2` 改成警告**：只有超过色板容量才报错。

## 七、配套改动

**`orb` 加回**：`--blacklist 'hair,face,head' --min-area 2.0` → 选出 8 张（原来的黑名单里有 `orb`，它只有 2.07% 面积、6 条细节，但它是腰侧那个银球，值得单独给一个裁片 + 一个 tag）：

```
legs 175.0 / drape 103.0 / sash_point 69.4 / sash 58.5
shoes 58.4 / bodice 49.9 / sleeve_r 44.6 / orb 23.8
```

**给被去重掉的部位补掩码**：读 `01-parts/parts_all.json` 的 `bbox_px`，取参考图该框内的非背景像素（`ref.min(axis=2) <= 238`）写成 `ex8m_<id>.png`。实测补出 `hair 4.69% / veil 4.68% / sleeve_l 4.17%`。

**`--picked` 校验**：`detail_colormap.py --picked` 会检查 zones 是否都在选中列表里。要用未选中的部位做色区，得先造一个含全部 id 的 `work/picked_all.json`。
