## 0 一句话

**三个系统分成两组，两组的坐标系不同，不能合并也不必合并：**

| 组 | 系统 | 坐标系 | 载体 |
|---|---|---|---|
| **参考侧** | **GrabTag** | 参考图的 (x, y) | 裁片 + 画布掩码 + `<tag>` |
| **生成侧** | layout bbox | 画布的 (x, y) | 一张 `--color-map` |
| **生成侧** | 色图 prompt | 画布的 (x, y) | 同一张 `--color-map`（或另一张） |

**只有生成侧那两个会抢色图，需要合并；GrabTag 走自己的通道，与它们无冲突。**

用户 2026-11-11 的原话：

> **grabtag 的标注在参考图上，layout 和色图 prompt 标注在生成图上**

## 1 两个坐标系（这是全文的前提）

```
参考图 1216×1632                      画布 1216×1632
┌─────────────────┐                  ┌─────────────────┐
│  <sash>  ← 裁片  │                  │                 │
│  <legs>  ← 裁片  │   GrabTag 负责   │  layout bbox    │
│  <bodice>← 裁片  │   「取哪一块」    │  色图 prompt     │
└─────────────────┘                  │  负责「画在哪儿」│
        ↓                            └─────────────────┘
   --ref-query-mask-por                     ↓
   （每块裁片一张画布掩码）              --color-map
   白 = 这块裁片可在此区域读取
```

**两者的交汇点只有一处**：掩码的形状决定了「这块裁片能在画布的哪些位置生效」。**掩码是画布尺寸的，但它约束的是参考的读取权限，不是绘制指令。**

## 2 GrabTag（参考侧）

### 2.1 它是什么

「提示词提到某个 tag，那一块才引用参考图对应裁片；不提就不引用。」

三个组件：

| 要求 | 实现 | 代码位置 |
|---|---|---|
| tag → 裁片 | `--ref-labels`（视觉 token 前缀换成 `<tag>:`） | `nodes_moss_image.py:141-152`、`moss_run.py:970` |
| tag → 画布区域 | `--ref-query-mask-por`（每块裁片一张画布掩码） | `moss_ref_mask.py:41-93` |
| 不提就不引用 | prompt 不写 `<tag>`，那块裁片不进上下文 | —（无代码，纯提示词） |

### 2.2 掩码的语义（节点自述）

> **Scope each reference separately: mask i is the canvas region allowed to read reference i. White = may read that reference, black = blocked for those image tokens.**
> **`so one crop can be bound to one body part`**

### 2.3 掩码在注意力里怎么生效

`comfy\ldm\moss_image\model.py:419-442`：

```python
allow = (rq > 0.5)[:, :, None]
region[:, 0, :H * W, nq:] = region[:, 0, :H * W, nq:].masked_fill(~allow, float("-inf"))
```

**逐图像 token 的开关**：白区保留、黑区填 `-inf`（softmax 后为 0）。**不是逐参考 token 的裁剪**，所以一块裁片只能在白区内被读到，但在白区内是全块可见的。

### 2.4 提示词必须反向指派

| 写法 | 例子 | 后果 |
|---|---|---|
| 正向（差） | `Picture 1 is the jewelled chest piece: …` | 裁片被当成**要画的对象**，容易画成漂浮物 |
| **反向（好）** | `Her upper chest and bust are covered by <bodice>.` | 主语是画布部位，裁片是**这处的素材**，天然带空间约束 |

**实测**（同裁片同参数，只换句式）：`vs参考 128.46 → 122.61`，锐度 `2.93 → 3.41`，人物外漂浮块 `1 → 0`。

### 2.5 实测数据（1216×1632 / 8 步 / seed 9001）

| 臂 | 参考 | vs参考 | 锐度 | 饱和度 | 人物外大块 |
|---|---|---|---|---|---|
| saA 整图 1 张 | 7752 tok | 127.80 | 3.38 | 16.34 | 0 |
| gt1 8 裁片，**无 tag 引用** | 1540 tok | 131.01 | 2.69 | 15.26 | 0 |
| gt2 8 裁片，**正向 `<Picture N>`** | 3147 tok | 128.46 | 2.93 | 18.35 | **1** |
| gt3 8 裁片，**反向 `<Picture N>`** | 3147 tok | 122.61 | 3.41 | 26.43 | 0 |
| **gt4 8 裁片，反向 `<tag>`** | 3147 tok | **121.13** | 3.27 | 24.33 | **0** |

**两条硬结论**：①prompt 里必须有引用（gt1 等于白挂）；②必须反向（gt3 比 gt2 好 5.85）。

完整实现、裁片预算、掩码陷阱见 **`notes\机制-GrabTag-当前实现.md`**。

## 3 layout bbox（生成侧）

| 项 | 内容 |
|---|---|
| **它是什么** | 一个 `layout.json` → 区域色图 + 方位文案的转换器 |
| **色图来源** | **矩形 bbox 自动画**（`moss_run.py:802` `_layout_to_colormap`） |
| **文案载体** | **方位描述**：`Region N (upper left): <paint_prompt>.`，拼到 prompt **最前面** |
| **核心语义** | 方位（upper/middle/lower × left/centre/right）+ 该区画什么 |
| **代码事实** | bbox 是 **yxyx、以画布中心为原点**（`:831` `y0, x0, y1, x1 = bb`，再 `+W//2, +H//2`）；色由 `_layout_palette(n)` 按黄金分割色相生成（`:746`） |

**三条已验事实**

1. **bbox 尺寸是最强控制手段**：240×200 → 140×115 → 100×80 使洞面积 8.34% → 4.91% → 1.59%；**文本写 `width of a hand` 只能到 3.80%，管不住**。
2. **对称必须靠 bbox**：文本写 `mirrored` 不管用（左右对称差 2.99 → 0.09 全靠 bbox 对称）。
3. **bbox 尺寸直接决定背景污染**：trio1（原框，legs 17.1%）四角污染 **49.4%**；trio2（`--max-area 12`）降到 **7.8%**。

**两个坑**

1. **绘制顺序必须按面积降序**（`:818-840`）——按 items 原序画，后画的大块会把先画的小块整块吃掉，实测 10 项只剩 7 个可见色区。
2. **`--color-map` 与 `--layout` 曾经互斥**（`:1017-1018` `SystemExit`）——那个检查已删除，`:309-318`/`:406-414` 本来就有兼容分支。

## 4 色图 prompt / 子区色图（生成侧）

| 项 | 内容 |
|---|---|
| **它是什么** | 手工造一张「灰底 + 1~3 个纯色块」的色图，配 `--region-prompt` 定向加密某处的纹样 |
| **色图来源** | 手写 numpy / PIL |
| **文案载体** | 颜色键：`the <颜色> area is <描述>`，追加到 prompt **尾部**（`moss_run.py:460-466`） |
| **核心语义** | 色块 = 一个**焦点框**，不是布局图 |
| **已验事实** | 腿部纹样梯度 5.27 → **6.84**（+30%，超过参考图自身 6.72）；**色块必须 ≤8% 画布** |
| **最重要一条** | **背景不能用白色**。白底会把姿态带跑（PA1-PA3 全变正面站定），**中灰 128 才保住姿态** |

**色差约束（决定一张色图最多开几个子区）**

| 候选 | hex | 与 palette11 最小距离 | 可用 |
|---|---|---|---|
| 洋红 | `#ff00ff` | 210 | ✓ |
| 纯蓝 | `#0000ff` | 239 | ✓ |
| 纯绿 | `#00ff00` | 220 | ✓ |
| 青 | `#00ffff` | 193 | ✗ |
| 黄 | `#ffff00` | 188 | ✗ |
| 春绿 | `#00ff80` | 232 | ✓ 但与 lime 只差 128，二者取一 |
| 紫 | `#8000ff` | 160 | ✗ |
| 橙 | `#ff8000` | 61 | ✗ |

**结论：一张色图最多三个子区（洋红 / 纯蓝 / 纯绿，两两 ≥255）。**

## 5 三者对照

| | **GrabTag** | layout bbox | 色图 prompt |
|---|---|---|---|
| **坐标系** | **参考图** | 画布 | 画布 |
| **载体** | 裁片 + 画布掩码 + `<tag>` | `--color-map` | `--color-map` |
| **文案格式** | `<tag>` 反向指派 | `Region N (upper left): …` | `the <hex> area is …` |
| **拼在哪** | 正文（部位句） | prompt **最前面** | prompt **尾部** |
| **核心语义** | 这块从参考的哪一部分取 | 这个方位画这个 | 这块重点画这个纹样 |
| **精度** | 裁片形状（贴合衣服） | 矩形框 | 手绘块 |
| **上限** | **8 张掩码** | 任 N | **3 个子区** |
| **和谁抢资源** | **谁也不抢** | 和色图 prompt 抢同一张色图 | 同左 |

**关键变化**：上一版说「三者抢同一张色图」，**只有后两个抢**。GrabTag 现在独立。

## 6 组合协议

### 6.1 能同时用

```
GrabTag（参考侧）  ─┐
                    ├─ 可以叠加，互不干扰
layout bbox        ─┤
                    │
色图 prompt        ─┘  ← 这两个必须合并成一张色图
```

### 6.2 生成侧两兄弟怎么合并（如果都要用）

1. **一张色图**：layout 的 bbox 色块 + 子区色块画在同一张上
2. **绘制顺序按面积降序**（`:818-840` 已改好）
3. **背景用中灰 128**（layout 默认白底，要给子区用必须改）
4. **文案统一成颜色键格式**——混两套（方位 + 颜色键）模型会打架

### 6.3 参数档

| 场景 | control-strength / end | 备注 |
|---|---|---|
| GrabTag + 深度图 | 0.5 / 0–0.5 | gt4 用的 |
| layout 单开 | 0.5 / 0–0.6 | 默认 |
| 色图 prompt 子区 | 0.6 / 0–0.6 | 需保住姿态 |

## 7 三种典型场景

### 场景 A：复刻一套衣服（外观相似度优先）

**用 GrabTag，不用 layout。**
```
8 块裁片 + 8 掩码 + 反向指派 → vs参考 121.13（优于整图参考 127.80）
```
layout 在这个场景没有净收益（trio2 127.50 ≈ 基线 127.80）。

### 场景 B：换姿势但保造型

**深度图 + layout bbox（限部位）+ GrabTag 裁片。**
色图负责「这块归你」，GrabTag 负责「从参考取哪块」。

### 场景 C：纹样加密

**子区色图（≤3 块，中灰底）+ `--region-prompt`。**
只圈需要加密的部位，其余别标。**色块 ≤8% 画布**。

## 8 已知冲突

| 冲突 | 现象 | 处置 |
|---|---|---|
| layout 白底 vs 子区需中灰 | 白底把姿态带跑 | 合并时把底改成 128 |
| 文案两套格式 | 混用模型打架 | 统一成颜色键 |
| 色块覆盖 | 大块吃掉小块 | 面积降序绘制 |
| **裁片丢整体构图** | 8 裁片 1540 tok 时 vs参考 131.01（比整图差） | 放大到 3147 tok（→121.13），或走混合模式（整图 + 2–3 裁片，**未实测**） |
| **GrabTag 饱和度偏高** | gt4 24.33 vs 整图 16.34 | 未解决；可加收敛句或减少裁片 |

## 9 一句话决策表

| 你要解决的问题 | 用哪个 |
|---|---|
| 这套衣服要像参考 | **GrabTag**（8 裁片 + 反向指派） |
| 某个部位的纹样要加密 | 子区色图（≤3 块，中灰底） |
| 某块画在画布哪个位置、多大 | layout bbox |
| 换姿势 | 深度图 + control |
| **三者都想用** | GrabTag 走参考侧、layout 色图 prompt 合并成一张中灰底色图 |
